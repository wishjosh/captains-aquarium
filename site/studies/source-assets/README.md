# 산호·암석 원본 및 수정 비교

> 2026-10-30 · 자산 비교용 실행 장면 · 최종 미술·실기기 채택 전

기존 선장(모자 중앙 앵무새·나무 스크류 포함)과 흰동가리 옆에서, 같은 지형과 조명·시점으로 기존 11군체 / 후보 원본 재질 / 후보 색·배치 조정의 세 모드를 비교한다. 오른쪽/왼쪽 구분 없이 장면을 끌면 회전하고 휠·두 손가락으로 확대한다. 정지와 잠영 자세 및 무채색을 선택할 수 있다. 잠영은 제자리 자세 비교이며 실제 이동·접근·수집 게임이 아니다. 기존 말미잘과 바닥을 비교 기준으로 이어 썼으므로 전체 서식처의 새 미술을 완성한 결과가 아니다.

## 실제 파일 검사

- Coral · rkuhlf: 원본 ZIP 1,076,746바이트, 내부 Coral.blend 1,076,612바이트, GLB 481,176바이트. 원본 블록에서 산호 물체 7개·모형 데이터 7개·재질 1개를 확인했고 GLB에서도 7모형·6,390삼각형·이미지 없음으로 확인했다.
- Low Poly Rocks · Michael Hooper: GLB 442,328바이트, 원래 1모형·650삼각형. 위치가 일치하는 정점과 삼각형 연결을 분석해 9개의 떨어진 덩어리로 분리했다. DAE 원본은 확보를 확인하지 못했고 수정·분리 검사는 GLB 기준이다.
- 암석에는 1,024×1,024 이미지 3장이 있다. 이미지 인코딩 합계는 376,087바이트다. 일반 RGBA와 전체 축소 단계를 가정한 단순 추정은 16MiB이며 실제 GPU 메모리 측정값이 아니다.
- 모듈은 부품별 바닥 중앙을 원점으로 맞추고 높이를 1단위로 정규화했다. 원본 법선·UV와 모든 삼각형을 보존했다. 텍스처가 없는 색 재질로 내보낸 산호 7종 모듈은 442,576바이트, 암석 9종 모듈은 50,040바이트다. 합친 모듈은 491,500바이트다.
- 각 배치는 동일한 geometry를 공유하며 크기·회전·재질만 바꾼다. 원본 파일은 assets의 original 파일과 작업대의 자료 폴더에 따로 보존한다. 변환 도구는 tools/prepare-source-asset-study.mjs이며 새 모형을 AI로 재생성하지 않는다.

## 검증 범위와 판단

부품 분리의 삼각형 보존·좌표 및 인덱스 유효성·출처와 이미지 의존 제거 검사 3개가 통과했다. PC 905×1247·렌더 배율 1.2에서 같은 시점·거리·조명·정지 자세로 워밍업 뒤 각 10초를 측정했다. 기존 813,324삼각형·59그리기 요청, 후보 원본 재질과 조정본 각 83,547삼각형·57요청이었다. 세 경우 모두 약 59.95fps·95% 프레임 16.8ms·33ms 초과 0/600회였다. 전체 지형·그림자 등 렌더러 카운터를 포함한 이 장면의 결과이며 GPU 시간 감소율이나 실제 스마트폰의 성능 보장이 아니다. 페이지는 비교할 자산을 함께 준비하므로 전체 상주 메모리·최초 준비 시간을 각 단일안의 배포 비용으로 해석하지 않는다.

후보 산호의 단순한 면과 가지는 캐릭터 스타일 비교에 유용하지만 굵고 단단한 가지와 가는 가지가 섞인 구성이다. 제주 연산호 한 종류의 최종 표현·종 정확성으로 채택하지 않는다. 암석은 단순한 부품으로 쓰기 쉽지만 기존 바닥과 자연스럽게 연결하는 지형 설계가 남는다. 실제 노트20 울트라·아이폰16 프로의 장시간 성능은 미검증이다.
